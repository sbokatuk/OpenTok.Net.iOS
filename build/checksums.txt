# SHA-256 of each OpenTok iOS download, keyed by archive name (<artifact>-<version>).
#
# Two artifacts are tracked, both fetched by build/fetch-opentok.sh:
#
#   OpenTok-iOS-<v>              the core SDK (pod OTXCFramework)      -> OpenTok.xcframework
#   OpenTok-iOS-Transformers-<v> the media transformers (pod           -> OpenTokTransformers.xcframework
#                                VonageClientSDKVideoTransformers)
#
# Vonage publishes no checksum manifest of its own alongside either download, so the hash is
# pinned here, in the repository, and the fetch script refuses to use an archive that does not
# match.
#
# That makes this file the trust anchor for the native code (OpenTok.xcframework) that gets
# linked into consumers' apps: a substituted or truncated archive fails the fetch instead of
# being bound and published. It also makes the build reproducible, since the download URL can be
# replaced in place without the version in the URL changing.
#
# To add a version, find the download URL from the pod's own CocoaPods podspec (the one
# `pod install` would fetch), download the archive and record its hash. For the core SDK:
#
#   v=2.35.1
#   pod=OTXCFramework                                            # or VonageClientSDKVideoTransformers
#   md5=$(printf '%s' "$pod" | md5sum | cut -d' ' -f1)           # or: md5 -q -s "$pod"
#   curl -s "https://cdn.cocoapods.org/Specs/${md5:0:1}/${md5:1:1}/${md5:2:1}/$pod/$v/$pod.podspec.json" \
#     | python3 -c 'import json,sys; print(json.load(sys.stdin)["source"]["http"])'
#   curl -fsSL -o archive.zip "<that URL>"
#   shasum -a 256 archive.zip
#
# Format: <artifact>-<version> <sha256>

# Older entries are kept rather than replaced: build/fetch-opentok.sh takes a version argument, so
# a previous SDK can still be fetched and verified without editing this file.
