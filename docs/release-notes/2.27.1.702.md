## What's changed

First release of `OpenTok.Net.iOS` from this repository: .NET for iOS / .NET MAUI bindings for
Vonage's (formerly TokBox's) native OpenTok iOS SDK — **OTXCFramework 2.27.1**, the same artifact
`pod install` would fetch, downloaded straight from Vonage's SDK release URL (resolved from the
pod's own CocoaPods podspec) and verified against a SHA-256 pinned in `build/checksums.txt`.

> **Package versions are `<OTXCFramework version>.<binding revision>`.** `2.27.1.702` is
> OTXCFramework `2.27.1`, binding revision `702`. The fourth component belongs to this repository
> and advances when the binding or packaging changes while the native SDK stays put. It does not
> restart at 1: the predecessor monorepo already published this same package ID up to `2.27.1.701`
> on nuget.org, and a lower revision here would make this release invisible to NuGet's
> highest-version resolution.

## What is bound, and why by hand

`ApiDefinition.cs` and `StructsAndEnums.cs` are hand-written against the real `OpenTok.framework`
headers, covering `OTSession`, `OTPublisher`/`OTPublisherKit`, `OTSubscriber`/`OTSubscriberKit`,
`OTStream`, `OTConnection` and `OTError`, plus their delegate protocols — session lifecycle,
connect/disconnect, publish a local stream, subscribe to a remote one, and the matching callbacks.

The package targets `net8.0-ios18.0`, `net9.0-ios18.0` and `net10.0-ios26.0`. No single .NET SDK
builds all three, so the build packs twice and merges the results — see `build/merge-packages.py`.
**No Mac Catalyst**: Vonage ships no `maccatalyst` slice for this SDK.

Unlike the sibling [`Net.Agora.iOS`](https://github.com/sbokatuk/Net.Agora.iOS) repository's
several *dynamic* xcframeworks, `OpenTok.xcframework`'s binary is a *static* `ar` archive, so it is
**embedded** into the binding assembly rather than carried as a loose native dependency.

## Tests

**Package-layout checks** run against the packed `.nupkg`, not the build output: a binding assembly
for every target framework, the embedded native payload (including the bundled
`selfie_segmentation.tflite` model) present and above a size floor, iOS device + simulator slices
only, and xcframework manifests that match the slices actually shipped.

**An on-simulator suite** (`tests/OpenTok.Net.iOS.DeviceTests`) installs the **packed package** into
a real iOS app and drives the raw binding: it asserts the native framework is actually loaded into
the process, resolves `OTSession`/`OTPublisher`/`OTSubscriber` through the Objective-C runtime,
constructs a session with a syntactically-valid unregistered API key, constructs a publisher, and
releases both. Nothing touches the network and no credentials are involved.

## Sample

`samples/OpenTok.Sample.iOS` is a MAUI app (iOS only) that connects to an OpenTok session and
publishes/subscribes video directly against `OTSession`/`OTPublisher`/`OTSubscriber` — an API
key/session/token entry, Connect/Disconnect/Publish buttons, and local + remote video views backed
by a hand-rolled MAUI handler, which is exactly what a consumer skipping a cross-platform façade
has to wire up. It consumes the packed package from `./artifacts`, so it doubles as proof the
package restores and links as published.

## CI

Pull requests pack, validate, build the sample and run the simulator suite against both extreme
target frameworks (`net8.0-ios18.0` and `net10.0-ios26.0` — net9 comes out of the same pack pass as
net8), then publish a `-beta.<pr>.<run>` prerelease; tagging `v2.27.1.702` publishes the package and
creates a GitHub release.
