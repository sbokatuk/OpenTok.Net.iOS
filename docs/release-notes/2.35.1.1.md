# OpenTok.Net.iOS 2.35.1.1

Moves the vendored SDK from **OTXCFramework 2.34.1 to 2.35.1**, and `OpenTok.Net.Transformers.iOS`
from `VonageClientSDKVideoTransformers` 2.34.1 to 2.35.1 with it — the two ride one version line.
Closes the upstream-drift issue the repository's own watch opened for this release.

The header delta is small: one new publisher capability, one new error code, one deprecated method
gone. The breaking change is the platform floor.

## Breaking: minimum iOS is now 17.0

OTXCFramework 2.35.1's podspec declares `"platforms": {"ios": "17.0"}`, up from 15.0, and both
`OpenTok.xcframework` and `OpenTokTransformers.xcframework` carry `MinimumOSVersion` 17.0 in their
`Info.plist`. That is the SDK's floor, not a choice made here. An app targeting iOS 15 or 16 cannot
take this package — stay on `2.34.1.2` (or `2.27.1.701` for iOS 13 and 14).

`SupportedOSPlatformVersion` moves to 17.0 in both packages, the device tests and the sample. The
sample had been left at 13.0 by the previous bump and is corrected here.

## Added: scalable video coding target mode (beta)

`OTPublisherKit` gains the two members 2.35.1 added to `OTPublisherKit.h`:

```csharp
publisher.SetTargetScalabilityMode("L1T3", out var error);
if (error is not null
    && (OTPublisherErrorCode)error.Code == OTPublisherErrorCode.PublisherInvalidScalabilityMode)
{
    // not one of L1T1, L1T2, L1T3, L2T1, L2T2, L2T3, L3T1, L3T2, L3T3
}

string? intended = publisher.TargetScalabilityMode; // the last value set, or null
```

The mode controls how many spatial (resolution) and temporal (frame rate) layers WebRTC encodes on
the Media Router path. It may be set before the media path is negotiated and is applied once it is;
when a non-SVC codec (VP8, H.264) is negotiated the closest mode is used instead, with spatial layers
forced to 1 (`L2T2` becomes `L1T2`). `TargetScalabilityMode` reports what was asked for, not what
was applied. Vonage marks the feature **beta**.

`OTPublisherErrorCode.PublisherInvalidScalabilityMode` (6006) is the new code, named after the
header's `OTPublisherInvalidScalabilityMode` minus the `OT` prefix, as with every other member of
that enum. It has a regression guard in `tests/OpenTok.Net.iOS.PackageTests` alongside the
video-event reasons, since a missing error code fails the same silent way.

## Removed: `OTVideoFrame.SetMetadata`

`setMetadata:error:` was deprecated in 2.34.1 and is gone from `OTVideoKit.h` in 2.35.1. The binding
is removed with it rather than left in place: a binding over a selector the framework no longer
implements compiles fine and throws `NSInvalidArgumentException` at the call site. The method was
an at-most-32-byte per-frame side channel with no replacement in the SDK; nothing in this
repository's sample or tests used it.

## Clarified: `OTStream.VideoDimensions`

No binding change — the header's own documentation changed. The property is now described as the
publisher's *capturer target* resolution, broadcast to every participant, rather than the dimensions
actually encoded or received; the publisher may be sending something smaller under bandwidth or CPU
pressure. Worth knowing if you were using it to size a view.

## Unchanged

- The system framework list the podspec declares is identical to 2.34.1, so the binding's
  `NativeReference` is untouched.
- The core payload grows slightly (~25 MB to ~27 MB compressed); the layout tests' floors were
  already below both.
